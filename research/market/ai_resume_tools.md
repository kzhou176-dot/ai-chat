## 2. 共性短板(我们能补的)

### 短板 1:STAR 法则自动化弱
- 大多数工具只做模板排版,不会**自动重写**成 STAR 法则(情境/任务/行动/结果)
- 改写建议多是模板化的"加量化数据",没有针对性

### 短板 2:行业垂直度低
- 都是通用模板,不懂"算法岗 vs 产品岗 vs 设计岗"的关键词差异
- 学生不知道"数据分析师简历"和"产品经理简历"该突出什么

### 短板 3:无模拟面试闭环
- 改完简历,不知道面试会问什么
- 没有"基于简历的模拟面试"联动

### 短板 4:中文简历质量差
- 很多工具是从英文翻译过来的,不熟悉中文简历习惯(教育/实习/项目 顺序)
- 一份简历投不同行业,中文用户没"3 份不同侧重版本"的工具

## 3. AIchat-Hub `scripts/resume.py` 设计要点

### 3 个内置角色(虚拟人化的差异化)
1. **简历导师(mentor)** — 通用改写建议、STAR 法则应用、量化数据补充
2. **行业 HR(hr)** — 关键词匹配、ATS 兼容性、行业侧重(算法/产品/运营/设计)
3. **学长学姐(senior)** — 实战经验、面试官关心点、"过来人"的口语化建议

### 3 份不同侧重简历(同 Profile,多版本)
- **技术版** — 项目 + 技能 + 实习(突出技术栈、GitHub、竞赛)
- **产品版** — 实习 + 项目 + 技能(突出用户思维、数据驱动、PRD 案例)
- **运营版** — 实习 + 项目 + 获奖(突出用户增长、活动策划、内容运营)

### 5 维评分(借鉴 `scoring.py` 模式,定制化)
1. **完整性(completeness)** — Profile 必填字段覆盖率
2. **量化(quantification)** — 动词 + 数字的密度
3. **STAR 法则合规** — 关键项是否含"情境/任务/行动/结果"四要素
4. **关键词相关性** — 简历关键词与目标岗位的匹配度
5. **格式(format)** — Markdown 结构、长度、列表化

### 沙箱安全(不依赖 LLM API key)
- 简历**生成/改写**用规则+模板(动词词典、量化模板、STAR 填充)
- 评分用纯规则(关键词匹配、计数、密度)
- LLM 只在"高级改写"可选(接 LLMClient,无 key 时走 mock)

## 4. 简历数据模型

```python
@dataclass
class ResumeProfile:
    """简历基础信息"""
    name: str
    school: str          # 学校
    major: str           # 专业
    degree: str          # 学历(本科/硕士/博士)
    graduation_year: int # 毕业年份
    target_position: str # 目标岗位(算法/产品/运营/...)
    internships: List[Internship]  # 实习
    projects: List[Project]         # 项目
    skills: List[str]               # 技能
    awards: List[str]               # 获奖
    self_intro: str = ""            # 自我介绍
```
