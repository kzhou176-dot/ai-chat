## 2. 共性短板(我们能补的)

### 短板 1:多角色模拟弱
- 大多数工具只有"技术面"或"行为面"之一,无**4 角色一站打通**(技术+行为+HR+压力)
- 学生想"全套模拟"得用 3-4 个工具切换

### 短板 2:中文行业垂直度低
- 海外工具中文不行,中文工具又不分行业
- 算法岗 / 后端岗 / 产品岗 / 运营岗 的提问风格差异大,通用工具答不到痛点

### 短板 3:反馈深度弱
- 多数只给"答得好/不好"标签
- 没有 STAR 法则的具体诊断("情境描述不清晰"、"量化数据缺失")

### 短板 4:无简历联动
- 改完简历,面试题没有基于简历生成
- 面试官问的项目细节,跟你简历上的项目对不上

### 短板 5:无复盘沉淀
- 模拟完了,没记录、没对比、没进步曲线
- 学生不知道自己"这周 vs 上周"进步多少

## 3. AIchat-Hub `scripts/interview.py` 设计要点

### 4 个内置面试官(多角色)
1. **技术面试官(tech)** — 算法 / 系统设计 / 编程题,关注深度 + 边界
2. **行为面试官(behavioral)** — STAR 法则,关注结构 + 量化
3. **HR 面试官(hr)** — 自我介绍 / 职业规划 / 文化匹配,关注表达 + 真诚
4. **压力面试官(pressure)** — 故意打断 / 否定 / 追问,关注抗压 + 应变

### 多轮对话(2-5 轮可配)
- 短面试:2 轮(快速诊断)
- 标准面试:3-4 轮(默认)
- 完整面试:5 轮(含压力面)

### 5 维评分(借鉴 resume.py / scoring.py 模式)
1. **逻辑性(logic)** — 回答结构是否清晰
2. **表达(expression)** — 语言流畅度
3. **技术深度(depth)** — 技术细节准确性
4. **应变(adaptability)** — 追问/压力下的表现
5. **匹配度(fit)** — 与目标岗位 JD 关键词匹配

### 3 个核心能力
1. **追问/澄清** — 面试官根据学生回答动态追问(基于规则)
2. **具体反馈** — 每轮回答后给"亮点 + 不足 + 改写建议"
3. **完整复盘** — 整场面试的总分 + 各维度曲线 + Top3 改进点

### 与 resume.py 联动(可选)
- 输入简历 Profile → 面试官基于"你的项目"提问
- 让学生在"自我介绍"后被问"你简历上那个 CubeSolver 项目,具体怎么实现的?"

### 沙箱安全
- 题库 + 评分用规则化(不依赖 LLM)
- 4 角色 + 10+ 题 = 40+ 题目静态库
- 评分用关键词匹配 + 长度 + 结构检测

## 4. 面试数据结构

```python
@dataclass
class Question:
    """一道面试题"""
    role: str             # tech / behavioral / hr / pressure
    text: str             # 题面
    key_points: List[str] # 关键要点(评分依据)
    difficulty: int       # 1-5
    follow_up: str = ""   # 追问(可选)

@dataclass
class InterviewSession:
    """一场面试"""
    interviewer: str       # 角色
    questions: List[Question]
    answers: List[str]     # 学生回答
    scores: List[float]    # 每题分数(0-1)
    feedback: List[str]    # 每题反馈
    round_idx: int = 0
    completed: bool = False
```
