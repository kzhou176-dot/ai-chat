02项目背景

Project Background

2.1 主题定义

本项目从"AIchat"(广义 AI 对话产品)切入,经过 cycle 0-1 的市场调研后,定位聚焦到虚拟人 AI chat——即:

文本 LLM 对话 + 形象(2D/3D) + 声音(TTS) + 记忆(长期 + 短期) + 动作(表情/手势) 的综合体

2.2 竞品格局

类别 代表产品 核心优势 短板
角色扮演 Character.AI、Janitor AI、CrushOn.AI 用户量大(1.77 亿浏览)、交互时长高(17+ 分钟) 不开源、NSFW 边界、数据本地化差
情感陪伴 Replika、星野(字节)、Glow(美图) 情感深度好,本土化强 多模态弱、长期记忆有限
数字人视频 HeyGen、Synthesia、D-ID、魔珐有言 商业化成熟(HeyGen ARR 3500 万 USD) 不开源、成本高、80GB 显存门槛
多模型客户端 NextChat 81.2K star、LobeChat 聚合多模型、5MB PWA 无虚拟人特性

2.3 我们的定位

不与上述任一产品正面对抗,而是构建开源 + 本地化 + 可学术化 + 多模型可插拔的虚拟人 AI chat 框架,服务:

  • 学术研究者(对比多模型 / 长期记忆 / 关系建模)
  • 独立开发者(快速搭建本地化虚拟人应用)
  • 内容创作者(虚拟陪伴 / IP 运营)
  • 隐私敏感用户(数据不出本地)

3.3 关键设计原则

零外部依赖

仅用 Python 3 标准库(urllib, json, http.server, threading),无需 pip install。一行启动,跨平台运行。

沙盒友好

每个 provider / 模块都有 mock fallback,无 API key 也能跑通。测试永远能 100% 通过,不受外部环境限制。

抽象层优先

每个外部依赖(LLM / TTS / Avatar)都用 ABC 抽象,真实 provider 是占位/可选实现,未来部署时无缝启用。

JSON 本地化

所有状态(Persona / Memory / Cost / Analytics)用 JSON 持久化,无数据库依赖,隐私优先。

04核心模块详解

Module Details

4.1 LLM Client · llm_client.py (274 行)

统一 6 个 LLM provider 的接口(OpenAI / DeepSeek / 智谱 / 通义 / Kimi / Anthropic),全部基于 OpenAI 兼容协议。沙盒无 key 时走 mock 路径。

关键能力

  • 统一 Message / ChatResponse dataclass
  • cost_usd 自动按 token 单价计算(7 provider 单价表)
  • 网络失败自动 fallback mock
  • 并行调用 N 个 provider(parallel_chat)

4.2 Persona · persona.py (187 行)

虚拟人数据类(性格/背景/系统提示/声音/形象),本地 JSON 存储。3 个内置虚拟人覆盖情感/专业/geek 三类场景。

4.3 Memory · memory.py (276 行)

长期记忆三件套:

  • Episodic:带时间戳的事件,自动剪枝保留 200 条
  • Semantic:事实/偏好,去重 + confidence 取 max
  • RAG 检索:Jaccard 关键词相似度 + 时间衰减(ep 30 天 / fact 60 天半衰期)+ 阈值 0.01 过滤噪音

4.4 Relationship · relationship.py (338 行)

4 阶段关系模型(陌生人 → 熟人 → 朋友 → 亲密),level 0-30 渐进,根据消息深度/情感/话题自动计算 delta,触发阶段晋升时返回 promoted 标志。

联动效应

  • 影响 称呼:您 → 你 → 亲爱的
  • 影响 语气:礼貌 → 友好 → 亲昵
  • 影响 记忆阈值:陌生人只记重要,亲密什么都记
  • 影响 解锁能力:陌生人只能基础对话,亲密可聊私密话题

4.5 Scene · scene.py (314 行)

场景/故事系统,7 种类型(daily/romance/adventure/fantasy/scifi/historical/mystery)+ 议程(关键词触发)+ 好感度事件(剧情推进)+ 3 个内置场景。

内置场景

  • 小爱 - 午后咖啡馆(日常 + 温馨 + 咖啡)
  • 小智 - 深夜 Hackathon(冒险 + 技术 + 肾上腺素)
  • 李医生 - 门诊咨询(专业 + 关怀)

4.6 TTS · tts.py (318 行)

3 provider 抽象层(mock / Edge TTS / 讯飞),沙盒不返回实际音频字节,只返回 SynthResult 元数据(时长/成本/缓存 key)。

关键设计

  • 7 声音库(中文 5 + 英文 2)
  • 沙盒安全:不返 audio_bytes,只 metadata
  • PERSONA_VOICE_MAP 映射 3 个虚拟人

4.7 Avatar Video · avatar_video.py (360 行)

嘴型同步抽象,4 provider(mock / Wav2Lip 4GB / SadTalker 8GB / MuseTalk 8GB),4 档质量(DRAFT 256p → ULTRA 1080p),4 视频格式。

4.8 Web 后端 · web.py (340+ 行)

零依赖 HTTP server(ThreadingHTTPServer),11 个 REST endpoint:

GET  /                       服务信息
GET  /api/personas           虚拟人列表
GET  /api/voices             TTS 声音(支持 ?lang= 筛选)
POST /api/chat               单 LLM 对话(+ persona 集成)
POST /api/compare            多 LLM 对比
POST /api/synthesize         TTS 合成
POST /api/avatar             嘴型同步
POST /api/avatar/tts         TTS + Avatar 串联
POST /api/score              5 维自动评分
GET  /api/cost               成本报告
GET  /api/analytics          用户行为分析

4.9 Scoring · scoring.py (320 行)

5 维自动评分,零 LLM Judge 依赖(标准库 only):

  1. 长度(理想区间 50-500,过长指数衰减)
  2. 格式(markdown/code/list/heading/bold/link 检测)
  3. 相关性(prompt 关键词覆盖度)
  4. 多样性(unigram + bigram Distinct-N)
  5. 响应时间(预算 3 秒内线性衰减)

4.10 Cost · cost.py (320 行)

成本追踪:7 provider 单价表 + 累计 + 按 provider/model/label 拆解 + 1000 条上限 + 80% 预算告警 + JSON 持久化。

4.11 Analytics · analytics.py (380 行)

用户行为分析 6 大功能:

  • overview 总览 / message_count / active_days
  • persona_distribution / relationship_stage_dist
  • funnel 漏斗(转化率) / cohort_retention(N 日留存)
  • value_per_user(消息+成本)

08关键洞察 & 经验教训

Insights & Lessons

8.1 工程纪律

15 分钟 1 cycle = 调研 5-6 min + 实践 5-6 min + 测试 3-4 min + 记录 3 min
  • 3 阶段都动:不跳过任何一阶段,即使时间紧
  • 用 edit 不用 write:保护大文件不被 clobber
  • 测试 100% 通过:硬约束,失败就修,不放过
  • 沙盒友好:mock fallback 让测试永远能跑

8.2 主题演进

从最初的"多模型 AI chat 聚合客户端"演进为"虚拟人 AI chat 框架"——这并非方向漂移,而是逐步聚焦:

  1. Cycle 0:广义 AIchat(什么都做)
  2. Cycle 1:多模型聚合客户端(差异化不足)
  3. Cycle 1 后段:虚拟人 AI chat(有形象/性格/记忆的差异化)

8.3 累积式开发

每个 cycle 都建立在前一个 cycle 的基础上,而不是平行开发:

  • Memory 复用 memory.py 的 tokenize(给 scoring/diversity 复用)
  • Relationship 与 Persona 集成(to_system_prompt)
  • Web 集成 LLM + TTS + Avatar + Score + Cost + Analytics(11 个端点)

8.4 遇到的关键挑战

arxiv 限流

5+ 个 cycle 累计 20+ 次 search 触发限流(429)。对策:30s 等待 + 改窄 query + web_search 补市场数据。

ChatResponse 字段不一致

不同 cycle 写的 ChatResponse 有/无 error 字段。web.py 用 getattr 兜底兼容。

沙盒无 API key

所有 provider 都需要 mock fallback,测试永远能跑。这是设计而非妥协。

stateful 测试污染

cost/analytics 测试在共享 tmp 目录会 load 旧 entries。改用每个测试独立 name 隔离。
